Blog repository initialised

The development blog now exists as its own first-party repository, Heretical-Solutions/Heretical-Blog, with its source checked out in the workspace at sites/blog/. Superproject registration is a separate later step. This post records what was set up; it makes no claim about any product being released.

What is in place

  • A Jekyll site using the Chirpy theme consumed as a packaged gem, pinned by a committed Gemfile.lock.
  • Site identity, UTC dates, search, categories, tags, Atom feed, syntax highlighting, and responsive light/dark mode. Comments, analytics, and PWA/offline caching are disabled.
  • Authoritative commands under eng/ for dependency restore, a local preview server, a production build into the ignored artifacts/site/ directory, and validation.
  • Product documentation for requirements, build, quick start, editorial process, deployment, and compatibility.

Publication model for now

Publication is deliberately manual. Once this source is approved and committed to master, the static site will be built and validated locally, then published as a deployment-only gh-pages branch for GitHub project Pages at /Heretical-Blog/. No site is live yet. Generated HTML never lands on master, and each deployment commit records the source revision it came from.

There are no GitHub Actions workflows, repository webhooks, or automatic draft generation in this initial phase. Build/deploy automation and event-driven editorial drafts are separate later proposals, each with its own approval gate.

Editorial process

_drafts/ is the single draft queue. A human reviewer promotes approved content into _posts/, and production builds exclude drafts, so unreviewed material cannot reach the published site.
